# Plan 06-01: Physical Database Isolation, Station Identity Enforcement & Peer REST Ingest Transport

## Objective
Isolate Station Alpha and Station Bravo into physically distinct SQLite WAL database instances (`alpha.db` and `bravo.db`) running on dedicated server ports (5051 for Alpha, 5052 for Bravo) with independent connection pools, zero shared in-memory variables or filesystem locks, strict local station identity enforcement (`IDENTITY_SPOOFING_BLOCKED`), and genuine HTTP/REST peer-to-peer forwarding with channel impairment simulation and cryptographic HMAC receipt reconciliation.

### Truths
- D-01: Unified Gateway + Direct Access — Each station daemon independently serves its own REST API and tactical console at its dedicated port (`:5051` for Alpha, `:5052` for Bravo), while port `:5050` serves the unified dual-feed console.
- D-02: REST Peer-to-Peer Transport with Impairment Pipeline — When Station Alpha dispatches a message addressed to Station Bravo, Alpha's delivery worker executes an HTTP POST request to Station Bravo's incoming ingest route (`http://127.0.0.1:5052/api/v1/endpoints/incoming`) routed through simulated channel impairments (latency, drop rates, air-gap outage simulation). Bravo persists the packet in `bravo.db` and returns a signed HMAC ACK, which Alpha reconciles in `alpha.db`.
- D-03: Strict Local Node Identity — `alpha.db` is initialized with Station Alpha (`endpoint-a`) designated as `is_local = True`. Any local draft attempting to author messages as `endpoint-b` directly into `alpha.db` is rejected with HTTP 403 `IDENTITY_SPOOFING_BLOCKED`. Station Bravo (`bravo.db`) enforces the identical constraint for `endpoint-b`.
- Dynamic Linker Safety on Apple Silicon — `import torch` strictly precedes any `numpy` or `scipy` imports across all entry points, routes, and test modules to prevent OpenBLAS symbol collision crashes (`SIGSEGV 139`).
- SQLite WAL Concurrency — Connection setup strictly executes `PRAGMA busy_timeout=5000` before `PRAGMA journal_mode=WAL` to prevent database lock contention between HTTP worker threads and delivery supervisor threads.
- Backward Compatibility — If `station_id` or `peer_url` is omitted, the backend defaults to nominal single-node evaluation, preserving 100% pass rate for all 218 existing tests.

### Key Links
- `POST /api/v1/messages` -> checks `current_app.config["STATION_ID"]` -> rejects remote authoring with HTTP 403 `IDENTITY_SPOOFING_BLOCKED`
- `QueueWorker.process_message()` -> detects remote recipient and `peer_url` -> calls `transport.transmit(message_dict, peer_url=...)`
- `transport.transmit_peer()` -> applies forward impairments -> POST `{peer_url}/endpoints/incoming` -> applies return impairments -> returns `ack_response`
- `POST /api/v1/endpoints/incoming` -> validates destination matches local node -> checks deduplication -> inserts message and `InboxItem` into receiver database -> returns `signed_ack_receipt`
- `QueueWorker.process_message()` -> receives `ack_response` -> updates sender message to `DELIVERED` with `signed_ack_receipt` in sender database without cross-database shared memory access
</must_haves>

<threat_model>
### T-06-01: Shared Database Lock Contention, Thread State Leaks & Filesystem Locking Failures
- **Threat:** If Station Alpha and Station Bravo share database handles, file descriptors, or in-memory session singletons, concurrent transactions will collide, generating `sqlite3.OperationalError: database is locked` or corrupting cross-station outbox leases.
- **Impact:** System instability, dropped deliveries, database corruption, and failure of physical node isolation.
- **Mitigation:**
  - `messaging/db.py` maintains separate engine instances in `_engines[db_path]` and separate session factories in `_session_factories[db_path]`.
  - Every connection explicitly sets `PRAGMA busy_timeout=5000` before `PRAGMA journal_mode=WAL`.
  - Auto-create directory `os.makedirs(os.path.dirname(os.path.abspath(db_path)), exist_ok=True)` ensures isolated paths like `Final-Project/data/alpha.db` and `Final-Project/data/bravo.db` never share files.

### T-06-02: Local Node Impersonation & Station Identity Spoofing
- **Threat:** An attacker or malicious client connects to Station Alpha's API port (5051) and attempts to submit a message claiming `sender_endpoint_id="endpoint-b"`, forging a message from Bravo inside Alpha's outbox.
- **Impact:** Identity spoofing, unauthorized command injection, and breach of audit integrity.
- **Mitigation:**
  - `messaging/models.py` tracks `is_local` on `Endpoint`.
  - `messaging/server.py` injects `app.config["STATION_ID"]`.
  - `messaging/api.py:submit_message()` compares `sender_endpoint_id` against `app.config["STATION_ID"]`. If they do not match, it immediately rejects the request with HTTP 403 `IDENTITY_SPOOFING_BLOCKED`.

### T-06-03: Ingest Replay Attacks, Duplicate Inboxes & Cryptographic HMAC Forgery
- **Threat:** If an adversary replays previously intercepted peer ingest packets against `POST /api/v1/endpoints/incoming`, or if repeated delivery attempts cause redundant inbox records, the recipient's inbox and event logs will be polluted with duplicates.
- **Impact:** Replay vulnerabilities, skewed message sequencing, and operator confusion.
- **Mitigation:**
  - `POST /api/v1/endpoints/incoming` queries `InboxItem` by `(recipient_endpoint_id, message_id)`.
  - If a message is already present, it emits a `DUPLICATE_DELIVERY_IGNORED` audit event and re-issues the identical pre-computed HMAC signature (`ACK-SIG:<id>:<hash>`) without creating duplicate inbox rows.
  - Receipt signatures are verified using `AckManager.generate_receipt_signature()` with the shared secret key.

### T-06-04: Peer Network Partitions, Outage Desynchronization & Silent Transport Failures
- **Threat:** If Station Bravo daemon is terminated, crashes, or suffers an air-gap network outage while Station Alpha dispatches messages, unhandled connection exceptions could crash Alpha's worker or silently discard pending messages.
- **Impact:** Loss of data during air-gap conditions, worker thread termination, and violation of the store-and-forward reliability guarantee.
- **Mitigation:**
  - `transport.transmit_peer()` wraps remote HTTP calls in explicit `requests.exceptions.ConnectionError` and `requests.exceptions.Timeout` handlers.
  - Network unreachable states cleanly map to `error_code="TRANSPORT_OFFLINE"` and `delivered_to_receiver=False`.
  - Alpha's `QueueWorker` catches the failure, transitions the message to `FAILED_RETRYABLE`, schedules exponential backoff with jitter, and safely releases the worker lease for future retry when Bravo recovers.
</threat_model>
