# Plan 03-01: Dynamic Link Failure Injection Controls and Browser IndexedDB Auto-Sync Validation

## Objective
Validate and refine dynamic impairment injection (outage toggle, latency, packet drop, ACK loss) via the Connectivity console and REST API (`/api/v1/sim/transport`), verify browser `IndexedDB` (`shadowcomm_outbox_db`) offline persistence, and ensure pending client messages flush automatically upon backend reconnection.

<must_haves>
- Transport simulation REST API (`GET /api/v1/sim/transport` and `POST /api/v1/sim/transport`) allows dynamic configuration of `is_online`, `latency_ms`, `drop_rate`, and `ack_loss_rate`.
- `ConnectivityView.tsx` controls and fault injection actions (`DROP_MESSAGE`, `DROP_ACK`, `CORRUPT_PAYLOAD`) execute cleanly with visual feedback notices.
- Client messages composed in browser while backend is offline persist durably in `IndexedDB` (`shadowcomm_outbox_db`) with status `PENDING_LOCAL`.
- When backend returns to `HEALTHY`, background sync flushes queued `IndexedDB` messages with idempotent keys and clears local outbox storage.
- Automated tests in `tests/test_offline_messaging.py` (`test_02_offline_transport_and_resumption` and `test_03_client_disconnected_from_backend`) pass with 100% assertions satisfied.
</must_haves>
