# Plan 03-02: Deterministic Crash, Restart Recovery, Idempotency Deduplication, and Exponential Backoff Retry Stress Test

## Objective
Validate that duplicate message submissions using identical `client_idempotency_key` safely return existing records with HTTP 200 without duplicate database rows, verify that background worker instances reclaim stale leases from terminated workers with exponential backoff and jitter, and run the 1,050-message high-volume simulation test verifying 100% recovery under severe network faults.

<must_haves>
- Submitting an identical `client_idempotency_key` via `POST /api/v1/messages` returns HTTP 200 with `is_new: false` and the existing `message_id`, without inserting a duplicate database record.
- When worker processes crash or terminate, stale leases (`lease_expires_at < now()`) are atomically reclaimed and rescheduled with exponential backoff and randomized jitter.
- `tests/test_offline_messaging.py` regression tests for crash recovery, lease reclamation, idempotency, and backoff (`test_04`, `test_05`, `test_06`, `test_08`, `test_09`) execute with 100% pass rate.
- `tests/test_simulation_1000_messages.py` executes successfully across 1,050 messages with 100% delivered rate and zero lost messages.
</must_haves>
