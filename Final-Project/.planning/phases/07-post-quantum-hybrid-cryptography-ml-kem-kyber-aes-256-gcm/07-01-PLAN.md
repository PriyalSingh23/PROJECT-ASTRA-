# Plan 07-01: Backend FIPS 203 ML-KEM-768 Core, Hybrid X25519 HKDF Derivation, Envelope v3 Binary Layout, Fallback Negotiation, Keyring Management & DMR Chunking

## Objective
Implement a pure-Python NIST FIPS 203 ML-KEM-768 key encapsulation mechanism with ephemeral X25519 hybrid key agreement, deriving symmetric AES-256-GCM session keys via HKDF-SHA256 for a new Envelope v3 format. Support automatic peer public key discovery across physical station databases, persistent disk keyrings, operator key rotation and zeroization APIs, dual-stack inbound auto-negotiation with legacy v2 fallback alerting, immediate HTTP 422 tamper rejection with security audit logging, and transparent DMR 280-byte burst fragmentation.

- D-04: Operator Key Rotation & Zeroization APIs — Explicit REST endpoints `POST /api/v1/crypto/rotate-keys` and `POST /api/v1/crypto/zeroize` with `SecurityAuditLog` event tracking.
- D-05: Strict Binary Framing for Envelope v3 — Layout is `[0x03 (1B)][0x01 (1B)][32B X25519 Eph PK][1088B ML-KEM CT][12B Nonce][16B Tag][Ciphertext]` with fixed 1150-byte header overhead.
- D-06: NIST/IETF Hybrid HKDF-SHA256 Derivation — `SS_hybrid = SS_X25519 || SS_MLKEM` (64 bytes); `K_session = HKDF-SHA256(SS_hybrid, salt=b"SHADOWCOMM-PQC-v3", info=b"ML-KEM-768/X25519/AES-256-GCM", length=32)`.
- D-07: Full Per-Message Ephemeral Forward Secrecy & DMR Chunking — Fresh ephemeral X25519 keypair and ML-KEM encapsulation per message; DMR chunker transparently slices ~1250B envelope into ~5 bursts (<HH> chunks).
- D-08: Strict Anti-Replay AAD Binding — Authenticated Associated Data `AAD = 0x03 || 0x01 || sender_endpoint_id || recipient_endpoint_id || message_id`.
- D-09: Dual-Stack Inbound Auto-Negotiation — Decrypts v3 (`0x03`) as PQC-secured (`pqc_verified=True`); auto-decrypts legacy v2 (`0x02`) with amber warning (`pqc_downgrade_warning=True`) and security audit event.
- D-10: PQC-Preferred Outbound Encryption — Defaults to Envelope v3; falls back to v2 if recipient PQC key is absent with audit warning.
- D-11: Explicit Schema Columns on Message — `envelope_version`, `pqc_scheme`, `pqc_verified`, `pqc_downgrade_warning` on `messages` table.
- D-12: Immediate Rejection of Tampered Envelopes — Rejects invalid ciphertexts/tags with HTTP 422 `CRYPTO_AUTHENTICATION_FAILED` and logs high-severity `SecurityAuditLog(action="PQC_TAMPER_DETECTED")`.
- Dynamic Linker Safety on Apple Silicon — `import torch` strictly precedes any `numpy` or `scipy` imports across all entry points, routes, and test modules to avoid OpenBLAS symbol collision crashes (`SIGSEGV 139`).
- SQLite WAL Concurrency — Connection setup strictly executes `PRAGMA busy_timeout=5000` before `PRAGMA journal_mode=WAL`.

<threat_model>
### T-07-01: Harvest-Now-Decrypt-Later Quantum Cryptanalysis
- **Threat:** Passive adversaries intercept and record encrypted tactical RF transmissions, storing them until cryptanalytically relevant quantum computers (CRQCs) can break classical ECDH (X25519) via Shor's algorithm.
- **Impact:** Total retroactive compromise of tactical communications, operational plans, and coordinates.
- **Mitigation:**
  - Implement NIST FIPS 203 ML-KEM-768 (Module-Lattice-Based KEM, Category 3 / AES-192 equivalent quantum security).
  - Combine ML-KEM-768 with ephemeral X25519 using HKDF-SHA256 dual-shared secret derivation (`SS_hybrid = SS_X25519 || SS_MLKEM`). Both classical and quantum assumptions must fail simultaneously to compromise the session key.

### T-07-02: Ciphertext Malleability & Active Replay / Impersonation Attacks
- **Threat:** An active adversary intercepts an encrypted Envelope v3 over simulated RF and re-transmits it to a different station or modifies plaintext headers (message ID, recipient ID).
- **Impact:** Spoofed tactical commands, replay of stale alerts, or redirection of messages to unintended nodes.
- **Mitigation:**
  - AES-256-GCM authenticated encryption enforces a 128-bit authentication tag over both ciphertext and Associated Authenticated Data (AAD).
  - Bind `AAD = 0x03 || 0x01 || sender_endpoint_id || recipient_endpoint_id || message_id`. Any alteration of routing identities or message ID causes tag verification to fail immediately.

### T-07-03: Silent Cryptographic Downgrade Attacks
- **Threat:** A man-in-the-middle attacker strips Envelope v3 headers or injects legacy v2 envelopes, tricking nodes into classical-only encryption without alerting operators.
- **Impact:** Inadvertent loss of post-quantum protection on vulnerable channels.
- **Mitigation:**
  - Inbound v2 messages trigger an immediate `SecurityAuditLog(action="PQC_DOWNGRADE_FALLBACK", severity="MEDIUM")` and `MessageEvent(event_type="PQC_DOWNGRADE_ACCEPTED")`.
  - Recipient flags message with `pqc_downgrade_warning = True`, surfaced in the UI as an illuminated amber alert `[CLASSICAL V2: NOT QUANTUM RESISTANT]`.

### T-07-04: Keyring Exposure, Memory Persistence & Unauthorized Key Reuse
- **Threat:** Sensitive private key material remains in process memory after decommission, or long-term static session keys allow passive decapsulation if compromised.
- **Impact:** Unauthorized message decryption across past and future sessions.
- **Mitigation:**
  - Fresh ephemeral X25519 keypair and fresh ML-KEM-768 encapsulation are generated per message (forward secrecy).
  - Keyrings stored on disk with `0600` permissions in `Final-Project/data/keys/`.
  - Provide `POST /api/v1/crypto/zeroize` to cryptographically overwrite key files with random bytes and zeroize memory keys on emergency purge.

### T-07-05: DMR 280-Byte MTU Fragmentation & Chunk Corruption
- **Threat:** Envelope v3 introduces 1150 bytes of encapsulation overhead, causing DMR packet count to increase from 1 to 5 bursts. If any chunk is corrupted or dropped over a lossy RF channel, partial packets could cause crashes or desynchronization.
- **Impact:** Failed message delivery, stalled receiver buffers, or out-of-order reassembly crashes.
- **Mitigation:**
  - Existing self-describing DMR chunker (`chunk_frame`) frames each burst with `<uint16 total><uint16 index>`.
  - Atomic frame retry policy: if any chunk fails or drops, the worker retries the entire frame from chunk 0 on subsequent backoff retry window.
  - Receiver reassembles all chunks in memory before passing to Envelope v3 decryption.
</threat_model>

    1. Constants:
       - `MLKEM_K = 3` (ML-KEM-768 rank)
       - `MLKEM_Q = 3329` (prime modulus)
       - `MLKEM_ETA1 = 2`, `MLKEM_ETA2 = 2`
       - `MLKEM_DU = 10`, `MLKEM_DV = 4`
       - `MLKEM_EK_BYTES = 1184` (encapsulation public key length)
       - `MLKEM_DK_BYTES = 2400` (decapsulation private key length)
       - `MLKEM_CT_BYTES = 1088` (ciphertext encapsulation length: 3*320 + 128)
       - `MLKEM_SS_BYTES = 32` (shared secret length)
    2. NTT & Ring Arithmetic:
       - Root of unity $\zeta = 17$, $\zeta^{128} \equiv -1 \pmod{3329}$. Precomputed bit-reversed powers of $\zeta$.
       - Forward Cooley-Tukey NTT converting degree-255 polynomial into 128 degree-1 elements in $\mathbb{Z}_q[X]/(X^2 - \zeta^{2r+1})$.
       - Inverse Gentleman-Sande NTT converting frequency coefficients back to standard polynomial form.
       - Base polynomial multiplication `base_mul(a0, a1, b0, b1, zeta)` mod $(X^2 - \zeta)$.
    3. Sampling Primitives:
       - `sample_ntt(rho, i, j)` using SHAKE-128 rejection sampling mod 3329.
       - `sample_poly_cbd(sigma, b, eta)` using SHAKE-256 centered binomial distribution sampling ($\eta=2$).
    4. Byte Encoding & Compression:
       - `byte_encode(poly, bits)` / `byte_decode(bytes, bits)` for 12, 10, 4, and 1-bit coefficients.
       - `compress(x, d)` / `decompress(y, d)`: $\lceil (2^d/q) \cdot x \rfloor \pmod{2^d}$.
    5. Public Key Encryption (ML-KEM-CPAPKE):
       - `k_pke_keygen(d_seed)` -> `(ek_pke, dk_pke)`
       - `k_pke_encrypt(ek_pke, m, coins)` -> `ct`
       - `k_pke_decrypt(dk_pke, ct)` -> `m`
    6. CCA Key Encapsulation (ML-KEM-CCA):
       - `mlkem768_keygen() -> Tuple[bytes, bytes]`: samples random seeds $d, z \in \{0,1\}^{256}$, returns `(ek, dk)` (1184B, 2400B).
       - `mlkem768_encaps(ek: bytes) -> Tuple[bytes, bytes]`: returns `(ciphertext, shared_secret)` (1088B, 32B).
       - `mlkem768_decaps(dk: bytes, ct: bytes) -> bytes`: implements Fujisaki-Okamoto transform with implicit rejection mod $z$. Returns 32-byte shared secret.
  </action>
