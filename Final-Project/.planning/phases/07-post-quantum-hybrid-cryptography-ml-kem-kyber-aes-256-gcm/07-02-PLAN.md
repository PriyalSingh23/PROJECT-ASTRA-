<threat_model>
### T-07-06: Operator Misinterpretation of Classical vs Post-Quantum Security
- **Threat:** An operator assumes all delivered messages possess quantum-safe encryption, overlooking messages that silently fell back to classical v2 due to missing peer keys.
- **Impact:** Critical strategic messages vulnerable to long-term adversary decryption without operator awareness.
- **Mitigation:**
  - Distinct visual hierarchy: PQC messages feature illuminated cyan `[PQC SECURED (ML-KEM-768)]` seals.
  - Fallback messages render high-contrast amber `[CLASSICAL V2: NOT QUANTUM RESISTANT]` caution badges.
  - The telemetry drawer displays an explicit security advisory explaining the absence of lattice-based post-quantum key encapsulation.

### T-07-07: Keyring Zeroization Accidental Trigger
- **Threat:** An operator accidentally clicks the "Emergency Zeroize" button, purging all station cryptographic key material during active operations.
- **Impact:** Immediate denial of service, inability to decrypt incoming peer messages, and drop in mission readiness.
- **Mitigation:**
  - Two-step confirmation modal with red warning text and explicit requirement to confirm action before dispatching `POST /api/v1/crypto/zeroize`.
  - Header status pill immediately changes to pulsing amber `[COMSEC: ZEROIZED]` to alert personnel.
</threat_model>
