# Plan 08-01: Backend Ad-Hoc Mesh Routing Engine, Multi-Factor Weighted Dijkstra, Binary Mesh Framing, Hop TTL Loop Guard, Custody Handshakes & Dynamic Reroute Recovery

## Objective
Implement a decentralized, opportunistic multi-hop ad-hoc mesh routing protocol for SHADOWCOMM across > 5 named ground, aerial UAV, and mobile convoy nodes connecting Station Alpha (port 5051) and Station Bravo (port 5052). Features include a multi-factor weighted Dijkstra algorithm that balances hop count, link latency, battery levels, queue depths, and storage limits; a 24-byte binary mesh bundle framing (`MSH`) with uint8 hop TTL decrements, uint16 visited node bitmasks for strict loop detection, and 16-byte signed custody transfer tokens (`CUSTODY_ACK`); and a fast 1.5s custody timeout triggering local alternate Dijkstra forwarding for sub-300ms route convergence during link dropouts.

### Truths
- D-01: Multi-Factor Weighted Dijkstra Routing Metric — The edge cost function incorporates hop count ($W_{\text{hop}}=1.0$), link latency ($W_{\text{latency}}=0.5 \cdot \frac{L_{uv}}{50}$), queue depth penalty ($1.5 \cdot (\frac{Q_v}{10})^{1.5}$), battery reserve penalty ($2.0 \cdot \frac{50-B_v}{40}$ for $B_v \le 50\%$; $10.0 + 4.0 \cdot \frac{10-B_v}{5}$ for $B_v \le 10\%$; $\infty$ for $B_v \le 5\%$), and storage penalty ($3.0 \cdot (\frac{S_v-80}{18})^2$ for $S_v > 80\%$; $\infty$ for $S_v \ge 98\%$), effectively steering routing around depleted or congested relays.
- D-02: Tiered RF Range & Elevation Adjacency Model — Adjacency between nodes is governed by physical altitude and distance: Ground-to-Ground $\le 15.0\text{ km}$ ($6.0\text{ units}$), Ground-to-UAV $\le 23.0\text{ km}$ ($9.2\text{ units}$), and UAV-to-UAV $\le 60.0\text{ km}$ ($24.0\text{ units}$). In theater coordinates ($1\text{ unit} = 2.5\text{ km}$), Station Alpha `[-9, 0, 0]` and Station Bravo `[+9, 0, 0]` are 45 km apart, necessitating multi-hop relaying across `relay-ground-01` (`[-5, 0, -1.5]`), `relay-convoy-01` (`[0, 0, 1.0]`), `relay-ground-02` (`[+5, 0, -1.5]`), `relay-uav-alpha` (`[-3, 4.5, 0.5]`), `relay-uav-bravo` (`[+3, 6.0, -0.5]`), and legacy `relay-aerial-sim-01` (`[0, 5.0, 0]`).
- D-03: Dual Edge Gateways — Station Alpha (`endpoint-a`) and Station Bravo (`endpoint-b`) act as edge source/sink gateways connected to nearby perimeter relays, routing end-to-end multi-hop bundles across the mesh interior.
- D-04: Hybrid Reactive Reroute + 5s Topology Heartbeat — Relays maintain a lightweight 5-second beacon polling cycle for background link health, supplemented by instantaneous reactive Dijkstra recalculation upon packet dropouts or custody timeouts.
- D-05: 25-Byte Outer Binary Mesh Bundle Header — Framing layout: `struct.pack("!3sBBBBH16s", b"MSH", flags, init_ttl, remaining_ttl, hop_count, visited_bitmask, bundle_uuid_bytes) + inner_payload`. Relays route based strictly on outer header metadata without decrypting or modifying the inner Envelope v3/v2 payload.
- D-06: Strict Decrement & Visited Set Guard — Remaining TTL decrements by 1 at each hop (drops on `remaining_ttl == 0` with audit event `BUNDLE_TTL_EXPIRED`); a 16-bit visited node bitmask check detects routing cycles (drops immediately with audit event `ROUTING_LOOP_DETECTED`).
- D-07: Per-Hop Custody Handshake + End-to-End Signed Receipt — Upstream relays release their storage queue leases upon receiving a 16-byte signed HMAC token `CUSTODY_ACK:<node_id>:<bundle_id>` from the downstream node, while the originating station maintains its delivery lease until Station Bravo issues the final end-to-end signed delivery receipt.
- D-08: Multi-Tier Tactical Priority Queue — `FLASH` (0x01) > `IMMEDIATE` (0x02) > `ROUTINE` (0x00). When relay storage exceeds 90%, lowest priority expired bundles are shed first.
- D-14: Fast Hop Custody Timeout (1.5s) & Local Alternate Forwarding — If a downstream custody ACK is not received within 1.5 seconds, the upstream relay flags the intermediate link as failed, queries Dijkstra for the next best alternate path excluding the offline node, and forwards the bundle immediately without requiring originator retransmission.
- Apple Silicon Dynamic Linker Safety — `import torch` strictly precedes `numpy` or `scipy` imports across all entry points, routes, and test modules to avoid OpenBLAS symbol collision crashes (`SIGSEGV 139`).
- Database Concurrency & Isolation — SQLite connections strictly execute `PRAGMA busy_timeout=5000` before `PRAGMA journal_mode=WAL`.

<threat_model>
### T-08-01: Broadcast Storms & Routing Loops in Dense Ad-Hoc Topologies
- **Threat:** Malicious or misconfigured relays re-broadcast message bundles cyclically, creating an exponential forwarding storm that exhausts battery, RF spectrum, and relay memory across the tactical grid.
- **Impact:** Total denial of service, rapid battery depletion of airborne UAV assets, and dropped operational traffic.
- **Mitigation:**
  - Strict 16-bit visited node bitmask encoded directly in the 24-byte binary mesh header (`uint16 visited_bitmask`).
  - Bit index is assigned deterministically per node (bits 0–7).
  - Any node detecting its own bit already asserted in `visited_bitmask` immediately drops the packet, logs `SecurityAuditLog(action="ROUTING_LOOP_DETECTED", severity="HIGH")`, and records `MessageEvent(event_type="ROUTING_LOOP_DETECTED")`.
  - Every hop strictly decrements `remaining_ttl`. If `remaining_ttl == 0`, packet is discarded with `BUNDLE_TTL_EXPIRED`.

### T-08-02: Transit Node Ciphertext Tampering & Payload Exposure
- **Threat:** An intermediate relay node (e.g. mobile convoy or captured ground relay) inspects or alters bundle payloads in transit, attempting to read tactical coordinates or inject corrupted instructions.
- **Impact:** Compromise of operational confidentiality or corruption of station database state.
- **Mitigation:**
  - Relays route strictly using the 24-byte outer cleartext binary header (`[MSH]...`).
  - The inner payload consists of an unmodified post-quantum Envelope v3 (or legacy v2) ciphertext with AES-256-GCM authentication tag bound to `sender_id:recipient_id:message_id` AAD.
  - Relays possess no private decapsulation keys and treat the inner payload as opaque immutable bytes. Any byte corruption causes tag verification failure and HTTP 422 `CRYPTO_AUTHENTICATION_FAILED` at the destination station.

### T-08-03: Upstream Buffer Exhaustion / Store-and-Forward Blackholes
- **Threat:** An upstream relay forwards a bundle to a downstream node that silently crashes, drops RF carrier, or gets jammed. If the upstream node discards its buffer immediately upon transmission without confirmation, the bundle is permanently lost.
- **Impact:** Complete failure of mission-critical tactical messaging without error notification.
- **Mitigation:**
  - Per-hop store-and-forward custody transfer: upstream relay holds bundle in durable memory until downstream node responds with a 16-byte signed HMAC token `CUSTODY_ACK:<node_id>:<bundle_id>`.
  - Upstream relay enforces a 1.5-second custody timeout. If unacknowledged, downstream node is marked unviable and Dijkstra computes a local alternate route around the failed node.

### T-08-04: Battery Exhaustion Exploitation via Traffic Flooding
- **Threat:** An adversary spams large volumes of non-critical routine messages toward aerial UAV relays, forcing them to remain active and deplete their batteries, bringing down airborne relays prematurely.
- **Impact:** Ground troops lose line-of-sight relay coverage due to drained drone batteries.
- **Mitigation:**
  - Multi-tier priority queue: `FLASH` > `IMMEDIATE` > `ROUTINE`.
  - Multi-Factor Dijkstra cost formula applies steep non-linear penalties as battery drops below 50% ($2.0 \cdot \frac{50-B}{40}$) and below 10% ($10.0 + 4.0 \cdot \frac{10-B}{5}$), diverting routing away from low-battery nodes.
  - Critical failsafe cutoff at $\le 5\%$ battery assigns infinite cost ($\infty$), completely shielding low-battery drones from transit forwarding.
  - Priority shedding: when node storage exceeds 90%, lowest priority expired bundles are shed first.
</threat_model>
