# Plan 06-02: Frontend Multi-Daemon Client Wiring, Dual Console Status HUD & Developer Launcher

## Objective
Upgrade the SHADOWCOMM web application and developer tooling into a distributed multi-daemon environment: wire the React console to independent Station Alpha (`http://127.0.0.1:5051/api/v1`) and Station Bravo (`http://127.0.0.1:5052/api/v1`) REST endpoints with real-time per-station connection HUD badges, decoupled polling loops, physical storage inspectors (`alpha.db` and `bravo.db`), graceful IndexedDB offline fallback on daemon disconnect, and a unified multi-station launcher script (`scripts/dev.sh --dual-station`) with single-command `trap cleanup` process lifecycle management.

### Truths
- D-01: Unified Gateway + Direct Access — The canonical web interface on port 5050 provides a side-by-side dual-feed monitoring dashboard querying Station Alpha (`:5051`) and Station Bravo (`:5052`) directly, while each station daemon also serves its own standalone console directly at `:5051` or `:5052`.
- D-02: Decoupled Failure States & Resilient Polling — If Station Bravo's daemon is terminated, Station Alpha's column remains completely interactive, displaying `ALPHA :5051 [ONLINE]`, while Station Bravo's column transitions to `BRAVO :5052 [DAEMON DISCONNECTED]` without crashing or blocking Alpha's outbox.
- D-03: Dual-Daemon Status HUD — Header renders dedicated dual-station indicators: `[● ALPHA :5051 • alpha.db]` in cyan (`#06B6D4`) and `[● BRAVO :5052 • bravo.db]` in emerald (`#10B981`), transitioning to red pulsing alerts (`[● OFFLINE]`) if either daemon becomes unreachable.
- D-04: Multi-Station Developer Launcher — `scripts/dev.sh --dual-station` spins up Station Alpha on port 5051 (`alpha.db`), Station Bravo on port 5052 (`bravo.db`), and the frontend console on port 5050 with single-command `trap cleanup INT TERM EXIT` terminating all child PIDs cleanly. Standalone mode is supported via `--station alpha` and `--station bravo`.
- Offline Outbox Routing — When composing a message on an offline station, drafts seamlessly queue into browser IndexedDB outbox (`outboxDb.ts`), displaying an amber badge. When the daemon restarts, `syncService` flushes pending drafts automatically.

<threat_model>
### T-06-05: Cross-Port CORS Policy Blocking & Console Request Hijacking
- **Threat:** If browser CORS policies block the React console (served from port 5050 or 5173) from issuing direct fetch requests to Station Alpha (`:5051`) or Station Bravo (`:5052`), the UI will fail silently with network errors.
- **Impact:** Broken UI feeds, non-responsive message composition, and false offline alarms.
- **Mitigation:**
  - `ApiClient` supports configurable `baseUrl` and dynamically matches port when browsed directly on `:5051` or `:5052`.
  - Backend `add_cors_headers` on both daemons explicitly permits origins `http://127.0.0.1:5050`, `http://localhost:5050`, `http://127.0.0.1:5051`, `http://127.0.0.1:5052`, and `http://127.0.0.1:5173`, including full preflight OPTIONS handling.

### T-06-06: Asymmetric Station Outages & UI Lockout Cascades
- **Threat:** If Station Bravo daemon crashes or is terminated by the operator, an unhandled promise rejection in `MessagesView.tsx` could halt all polling loops, freezing Station Alpha's column and preventing outbox refreshes on the healthy node.
- **Impact:** Cascade failure across independent stations, violating physical and operational fault isolation.
- **Mitigation:**
  - Alpha and Bravo polling queries are wrapped in independent `.catch()` handlers.
  - Per-station health state (`isAlphaOnline`, `isBravoOnline`) is maintained independently in component state.
  - Composing on an offline station gracefully routes to browser IndexedDB offline outbox with an explicit notice instead of throwing an unhandled exception.

### T-06-07: Zombie Daemon Processes & Address-In-Use Port Collisions
- **Threat:** When terminating `scripts/dev.sh` via `Ctrl+C`, child processes for Station Alpha or Station Bravo could remain orphaned in the background, holding ports 5051 or 5052 open and causing `Errno 48 Address already in use` on subsequent launches.
- **Impact:** Developer friction, failed test runs, and stale daemon code execution.
- **Mitigation:**
  - `scripts/dev.sh` registers a robust `trap cleanup INT TERM EXIT` that iterates over and kills all recorded PIDs (`ALPHA_PID`, `BRAVO_PID`, `GATEWAY_PID`, `VITE_PID`).
  - Pre-flight port checks in `dev.sh` detect and clear existing listeners on 5050, 5051, 5052, and 5173 before launching.
  - `scripts/stop_dev.sh` aggressively terminates listeners across all 4 ports using `lsof -ti :5050 :5051 :5052 :5173 | xargs kill -9`.
</threat_model>
