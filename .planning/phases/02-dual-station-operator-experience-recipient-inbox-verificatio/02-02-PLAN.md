# Plan 02-02: Real-Time Lifecycle Event Polling, Visual Delivery Indicators, and End-to-End UI Verification

## Objective
Implement auto-polling and visual stage pipeline indicators for the message audit timeline panel in `frontend/src/components/MessagesView.tsx`, and add comprehensive regression test `test_22_recipient_inbox_and_timeline_events` in `tests/test_offline_messaging.py` verifying full lifecycle audit event tracking (`MESSAGE_ENQUEUED` → `LEASE_ACQUIRED` → `INBOX_PERSISTED` → `ACK_VALIDATED_DELIVERED`) and recipient inbox queries via Flask REST API.

<must_haves>
- Real-time periodic polling (1500ms interval) of `/api/v1/messages/<id>/events` while a non-terminal message is selected in `MessagesView.tsx`, plus a manual refresh button.
- Visual 4-stage pipeline tracker in the details sidebar (`MESSAGE_ENQUEUED` → `LEASE_ACQUIRED` → `INBOX_PERSISTED` → `ACK_VALIDATED_DELIVERED`) highlighting the current milestone reached.
- Chronological event log with human-readable timestamps, transition tags, and expandable JSON metadata.
- Automated unit/integration test `test_22_recipient_inbox_and_timeline_events` in `tests/test_offline_messaging.py` verifying:
  - Message submission produces `MESSAGE_ENQUEUED` event.
  - Worker delivery produces `LEASE_ACQUIRED` and `INBOX_PERSISTED` events.
  - ACK processing produces `ACK_VALIDATED_DELIVERED` event with `signed_receipt`.
  - `GET /api/v1/endpoints/endpoint-b/inbox` returns the verified record.
  - `GET /api/v1/messages/<msg_id>/events` returns all 4 chronological stages in exact order.
- Full test suite passes: `pytest tests/test_offline_messaging.py -v`.
</must_haves>
