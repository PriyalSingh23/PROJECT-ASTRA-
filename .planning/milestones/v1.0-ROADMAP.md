## Phase Details

### Phase 1: Dual-Endpoint Reliable Messaging & Verified Receipt Reconciliation

**Goal**: Complete end-to-end reliable simulated messaging between Station Alpha and Station Bravo with verifiable HMAC signed receipts.  
**Depends on**: Nothing (first phase, builds on existing 55-test foundation)  
**Requirements**: MSG-01, MSG-02, MSG-03, MSG-04, MSG-05  
**Success Criteria** (what must be TRUE):
  1. `Message` SQLAlchemy model in `messaging/models.py` declares `signed_ack_receipt` and returns it in `to_dict()`.
  2. `AckManager.process_ack_at_sender()` populates `message.signed_ack_receipt` with the verified HMAC signature.
  3. Running `python -m messaging.server --with-worker` or `scripts/dev.sh` automatically leases and delivers queued messages without requiring manual separate worker processes.
  4. Messages sent from Station Alpha to Station Bravo transition from `QUEUED` $\rightarrow$ `SENDING` $\rightarrow$ `DELIVERED`, and render the green "ACK Verified" badge and signature receipt in the UI.
  5. `pytest tests/test_offline_messaging.py -v` passes with explicit assertions validating `signed_ack_receipt`.

**Plans**: 2 plans
- [x] 01-01: Model column, serialization, and AckManager signature reconciliation.
- [x] 01-02: Worker auto-launch / single-command execution and UI verified receipt rendering.

### Phase 2: Dual-Station Operator Experience & Recipient Inbox Verification

**Goal**: Enable side-by-side or fast identity toggling between Station Alpha and Station Bravo with true recipient inbox verification.  
**Depends on**: Phase 1  
**Requirements**: UI-01, UI-02, UI-03  
**Success Criteria** (what must be TRUE):
  1. Operator can switch active station identity between `endpoint-a` and `endpoint-b` with zero UI latency or state loss.
  2. UI queries `/api/v1/endpoints/<id>/inbox` to verify that incoming messages exist in recipient's durable storage.
  3. Message details sidebar renders the complete chronological lifecycle event log (`MESSAGE_ENQUEUED` $\rightarrow$ `INBOX_PERSISTED` $\rightarrow$ `ACK_VALIDATED_DELIVERED`).

**Plans**: 2/2 plans complete
**Wave 1**
- [x] 02-01: Connect recipient inbox REST query into conversation stream.

**Wave 2** *(blocked on Wave 1 completion)*
- [x] 02-02: Dual-station identity selector and audit timeline drawer in React UI.

### Phase 3: Fault Injection, Offline Outages & Client Re-Sync

**Goal**: Validate store-and-forward resilience across severed connections, latency, packet drops, client IndexedDB syncing, and server crash recovery.  
**Depends on**: Phase 2  
**Requirements**: FLT-01, FLT-02, FLT-03, FLT-04  
**Success Criteria** (what must be TRUE):
  1. Toggling offline mode in the Connectivity view pauses queue delivery; messages queue safely in SQLite.
  2. Messages composed in browser while backend is offline persist in IndexedDB and flush automatically upon reconnection.
  3. Resubmitting identical `client_idempotency_key` returns the existing message without duplicate row creation.
  4. Reclaiming stale leases automatically reschedules failed attempts with exponential backoff and jitter.

**Plans**: 2/2 plans complete
**Wave 1**
- [x] 03-01: Backend Fault Injection, Startup Sweep & Connectivity Impairment Controls.

**Wave 2** *(blocked on Wave 1 completion)*
- [x] 03-02: Browser Offline Outbox Sync, Idempotency Feedback & Telemetry HUD.

### Phase 4: Tactical Multi-Transport Broker & Hardware Safety Lockout

**Goal**: Enforce unified transport routing rules, DMR packet limits, and tactical safety lockouts.  
**Depends on**: Phase 3  
**Requirements**: TRN-01, TRN-02, TRN-03, TRN-04  
**Success Criteria** (what must be TRUE):
  1. `TransportManager` dispatches only to transports with readiness `READY` or `SIMULATION_ONLY`.
  2. Motorola TMS adapter rejects or fragments payloads exceeding 280 bytes.
  3. STAR-V tactical radio adapter remains permanently `LOCKED_OUT` for physical RF transmission.
  4. Relay nodes manager reports telemetry (battery, temp, queue size) with decoupled flight safety controls.

**Plans**: 2/2 plans complete
**Wave 1**
- [x] 04-01: Transport adapter contracts and DMR 280-byte ceiling validation.

**Wave 2** *(blocked on Wave 1 completion)*
- [x] 04-02: STAR-V safety lockout and relay telemetry monitoring.

### Phase 5: Research Lab Model Governance & SDR Physical Layer

**Goal**: Verify model checkpoint integrity, Apple Silicon MPS hardware acceleration, and GNU Radio / USRP flowgraph readiness.  
**Depends on**: Phase 4  
**Requirements**: RSH-01, RSH-02, RSH-03, RSH-04

  4. GNU Radio transceivers and USRP UHD streaming scripts operate at $245.76\text{ kS/s}$ and $2.484\text{ GHz}$.
