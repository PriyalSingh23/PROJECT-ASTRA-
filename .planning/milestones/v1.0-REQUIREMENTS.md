# Requirements: SHADOWCOMM — Reliable Tactical Communications & Research Platform

**Defined:** 2026-10-16  
**Core Value:** Deliver reliable, verified, and tamper-resistant messages between operational endpoints (Station Alpha and Station Bravo) through persistent offline queues, signed acknowledgements, and crash-resilient store-and-forward architecture with zero data loss.

---

## v1 Requirements

### 1. Reliable Messaging & Signed Receipts (MSG)

- [x] **MSG-01**: `Message` SQLAlchemy model declares `signed_ack_receipt = Column(Text, nullable=True)` and serializes it in `Message.to_dict()`.
- [x] **MSG-02**: `AckManager.process_ack_at_sender()` persists the validated cryptographic receipt signature into `message.signed_ack_receipt`.
- [x] **MSG-03**: Backend server (`messaging/server.py` / `app.py`) provides an optional embedded in-process queue delivery worker thread so standalone single-process execution automatically processes queued messages.
- [x] **MSG-04**: React UI conversation stream renders the green double checkmark (`CheckCheck`) "ACK Verified" badge with the receipt signature on delivered messages.
- [x] **MSG-05**: Automated unit test suite verifies `signed_ack_receipt` persistence, delivery round-trip, and duplicate ACK suppression.

### 2. Dual-Station Operator Experience & Recipient Inbox (UI)

- [x] **UI-01**: React UI provides clear, intuitive active station switching or side-by-side monitoring between Station Alpha (`endpoint-a`) and Station Bravo (`endpoint-b`).
- [x] **UI-02**: React UI queries and validates against the recipient's true inbox (`GET /api/v1/endpoints/<id>/inbox`) rather than relying solely on the sender's outbox query.
- [x] **UI-03**: Real-time message audit timeline panel displays chronological events (`MESSAGE_ENQUEUED` → `LEASE_ACQUIRED` → `INBOX_PERSISTED` → `ACK_VALIDATED_DELIVERED`).

### 3. Fault Tolerance, Offline Resilience & Client Outbox (FLT)

- [x] **FLT-01**: Simulated link transport supports dynamic impairment injection (outage toggle, latency, packet drop, ACK loss) via UI and REST API.
- [x] **FLT-02**: Client messages composed while backend is offline persist in browser `IndexedDB` (`shadowcomm_outbox_db`) and automatically flush to backend upon link recovery.
- [x] **FLT-03**: Duplicate message submissions using the same `client_idempotency_key` are safely deduplicated with idempotent HTTP 200 responses.
- [x] **FLT-04**: Background worker reclaims stale leases from crashed workers and reschedules delivery attempts using exponential backoff with jitter.

### 4. Tactical Interoperability & Hardware Safety (TRN)

- [x] **TRN-01**: `TransportManager` validates transport readiness (`READY`, `SIMULATION_ONLY`, `LOCKED_OUT`, `OFFLINE`) before dispatching payloads.
- [x] **TRN-02**: Motorola MOTOTRBO TMS adapter enforces 280-byte DMR packet ceilings and XCMP protocol simulation.
- [x] **TRN-03**: STAR-V tactical SDR adapter enforces a strict software safety lockout preventing unauthorized physical RF transmission.
- [x] **TRN-04**: Relay node manager provides store-and-forward telemetry (battery, temp, queue size) with decoupled flight safety failsafes.

### 5. Research Lab, Model Governance & SDR Physical Layer (RSH)

- [x] **RSH-01**: Research Lab verifies SHA-256 digest of PyTorch model checkpoints against `export_manifest.json` before loading.
- [x] **RSH-02**: Research Lab detects Apple Silicon Metal Performance Shaders (MPS) hardware acceleration with deterministic CPU fallback.
- [x] **RSH-03**: Interactive research console displays empirical BER vs SNR curves, I/Q constellations, and 8-domain EW statistics battery.
- [x] **RSH-04**: GNU Radio Companion flowgraphs (`tx_lpi_v4.grc`, `rx_lpi_cgan.grc`) and Ettus USRP UHD drivers operate at $245.76\text{ kS/s}$ and $2.484\text{ GHz}$.
