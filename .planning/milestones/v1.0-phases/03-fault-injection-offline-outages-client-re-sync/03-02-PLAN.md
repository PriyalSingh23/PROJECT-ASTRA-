<threat_model>
### T-03-03: Multi-Tab Outbox Sync Race Conditions and Duplicate Queue Submission
- **Threat:** Multiple browser tabs open concurrently on Station Alpha attempt to flush the offline IndexedDB outbox simultaneously upon link recovery, causing redundant network submissions, lock contention, or race conditions during local item deletion.
- **Impact:** Duplicate network traffic, database concurrency errors, and inconsistent local outbox counts across tabs.
- **Mitigation:**
  - `syncService.ts` coordinates background flushes using `navigator.locks.request('shadowcomm_outbox_sync')`, guaranteeing exactly one leader tab flushes the queue.
  - Broadcast updates to secondary tabs via `BroadcastChannel('shadowcomm_outbox_channel')`.
  - Backend unique constraint `uq_sender_idempotency` ensures that even in edge cases, identical keys return HTTP 200 without duplicate row insertion.
  - Sync reconciliation: when a message returns HTTP 200 (`is_new: false`), the local item is safely purged from IndexedDB without raising an error.

### T-03-04: Client Storage Exhaustion via Unbounded Offline Message Buffering
- **Threat:** Uncontrolled message drafting while disconnected exhausts browser storage quotas, leading to silent message drops or storage exceptions.
- **Impact:** Critical message loss during extended tactical air-gap operations.
- **Mitigation:**
  - Execute `navigator.storage.persist()` on app boot to request durable quota protection.
  - Enforce a strict buffer ceiling of 500 messages in `outboxDb.saveMessage()`.
  - Trigger prominent amber warning alert when local outbox exceeds 400 messages (`isStorageNearCeiling()`).

### T-03-05: Double-Click Rapid Multi-Submission Race Condition
- **Threat:** An operator clicking "Transmit Packet" multiple times in rapid succession generates multiple distinct client UUIDs for the same draft, creating unwanted duplicate transmissions.
- **Impact:** Duplicate orders or sitreps broadcast over tactical link.
- **Mitigation:**
  - Immediate client-side button disablement upon click with animated spinner (`isSubmitting` state).
  - Draft-bound idempotency key generation: key is locked once per draft edit, not regenerated on submit clicks.
</threat_model>

   - Provide `SyncService` singleton coordinating multi-tab Web Locks and BroadcastChannel:
     ```typescript
     type SyncCallback = () => void

     class SyncService {
       private channel: BroadcastChannel | null = null
       private listeners: Set<SyncCallback> = new Set()
       private isFlushing: boolean = false

       constructor() {
         if (typeof window !== 'undefined' && 'BroadcastChannel' in window) {
           this.channel = new BroadcastChannel('shadowcomm_outbox_channel')
           this.channel.onmessage = (event) => {
             if (event.data?.type === 'OUTBOX_MUTATED') {
               this.notifyListeners()
             }
           }
         }
         outboxDb.initPersistence().catch(() => {})
       }

       subscribe(cb: SyncCallback): () => void {
         this.listeners.add(cb)
         return () => this.listeners.delete(cb)
       }

       private notifyListeners() {
         this.listeners.forEach((cb) => {
           try { cb() } catch {}
         })
       }

       broadcastMutation() {
         this.notifyListeners()
         if (this.channel) {
           this.channel.postMessage({ type: 'OUTBOX_MUTATED', timestamp: Date.now() })
         }
       }

       async flushOutbox(): Promise<{ flushed: number; duplicates: number; failed: number }> {
         if (this.isFlushing) return { flushed: 0, duplicates: 0, failed: 0 }

         const executeFlush = async () => {
           this.isFlushing = true
           let flushed = 0
           let duplicates = 0
           let failed = 0
           try {
             const items = await outboxDb.getAllMessages()
             const pending = items.filter((i) => i.sync_status === 'PENDING_LOCAL')

             for (const item of pending) {
               try {
                 const res = await api.submitMessage({
                   client_idempotency_key: item.client_idempotency_key,
                   sender_endpoint_id: item.sender_endpoint_id,
                   recipient_endpoint_id: item.recipient_endpoint_id,
                   payload: item.payload,
                   message_type: item.message_type || 'TEXT',
                   priority: item.priority || 1,
                   expires_in_seconds: item.expires_in_seconds || 86400,
                 })
                 // Seamless reconciliation: delete local item on both 201 (new) and 200 (duplicate)
                 await outboxDb.deleteMessage(item.client_idempotency_key)
                 if (res.is_new === false) {
                   duplicates++
                 } else {
                   flushed++
                 }
               } catch (err: any) {
                 failed++
                 await outboxDb.updateSyncStatus(
                   item.client_idempotency_key,
                   'FAILED_SYNC',
                   err.message || 'Transmission failed'
                 )
               }
             }
           } finally {
             this.isFlushing = false
             this.broadcastMutation()
           }
           return { flushed, duplicates, failed }
         }

         // Elect flush leader via Web Locks API if supported
         if (typeof navigator !== 'undefined' && 'locks' in navigator) {
           return await navigator.locks.request('shadowcomm_outbox_sync', { ifAvailable: true }, async (lock) => {
             if (!lock) {
               // Another tab is currently flushing the outbox
               return { flushed: 0, duplicates: 0, failed: 0 }
             }
             return await executeFlush()
           })
         } else {
           // Fallback to in-process execution
           return await executeFlush()
         }
       }
     }

     export const syncService = new SyncService()
     ```
