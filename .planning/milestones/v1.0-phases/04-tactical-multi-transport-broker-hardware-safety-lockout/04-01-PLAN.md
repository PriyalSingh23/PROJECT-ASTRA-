# Plan 04-01: Backend Multi-Transport Broker, DMR Chunking & Hardware Safety Lockout

## Objective
Implement an enterprise-grade tactical multi-transport routing broker for SHADOWCOMM. ### Truths
- `RETRYABLE_ERROR_CODES` in `Final-Project/messaging/retry_policy.py` contains `"ROUTE_UNAVAILABLE"` and `"STARV_SAFETY_LOCKOUT_BLOCKED"` so messages held due to route unreachability or safety lockout are durably preserved under exponential backoff with state `FAILED_RETRYABLE` rather than dropped.
- Operator can pin an active primary transport (persisted in SQLite `system_settings` table under `active_transport`) and toggle auto-failover (persisted under `auto_failover`, default `True`).
- When active transport is offline or locked out and `auto_failover` is `True`, `DispatchRouter` transparently fails over to secondary operational adapters (`READY` or `SIMULATION_ONLY`) or simulated RF.
- When active transport is offline or locked out and `auto_failover` is `False`, `DispatchRouter` returns `"ROUTE_UNAVAILABLE"` (or `"STARV_SAFETY_LOCKOUT_BLOCKED"` if pinned to STAR-V), holding the message in SQLite durable queue.
- Payloads exceeding 276 bytes dispatched over Motorola MOTOTRBO are transparently split into self-describing 280-byte burst frames (`<uint16 total><uint16 index><data>`).
- If any chunk in a multi-burst DMR transmission fails, the attempt immediately aborts and all chunks are re-transmitted atomically from chunk 0 on subsequent backoff retry window.
- Physical RF transmission on STAR-V tactical radio is permanently locked out in software (`readiness = TransportReadiness.LOCKED_OUT`, `connection_state = TransportConnectionState.OFFLINE`, `command_transmit()` raises `StarVSafetyLockoutError`).
- Any transmission attempt targeting or pinned to STAR-V logs an explicit `STARV_SAFETY_LOCKOUT_BLOCKED` event in `MessageEvent` and a high-severity `SecurityAuditLog` entry.
- Dry-run lockout verification endpoint `POST /api/v1/transports/starv/test-lockout` safely tests both soft refusal (`send()`) and hard command lockout (`command_transmit()`).
- `RelayNode.to_dict()` provides dual-key compatibility (`battery_percentage` / `battery_level_pct`, `storage_used_pct` / `storage_usage_pct`, `queue_depth` / `queued_bundles_count`, `flight_failsafe_independent` / `is_independent_payload`, `failsafe_cutoff_active`).

- Aerial relay node communications payload is strictly decoupled from vehicle flight safety systems (`flight_failsafe_independent = True`).
- Apple Silicon Mac dynamic linker safety: `import torch` strictly precedes `numpy` or `scipy` across all Python files and tests.

<threat_model>
### T-04-01: Route Unreachability, Unroutable Message Drops, or Uncoordinated Failover
- **Threat:** If an operator pins an offline or locked-out transport and auto-failover is disabled, an unhandled exception or unclassified error could cause the message to drop or transition to `FAILED_FINAL`, violating the zero-silent-packet-loss guarantee. Alternatively, multi-process worker nodes might fail to observe failover configuration changes.
- **Impact:** Unrecoverable packet loss across tactical radio networks and loss of operator control.
- **Mitigation:**
  - Register `"ROUTE_UNAVAILABLE"` and `"STARV_SAFETY_LOCKOUT_BLOCKED"` into `RETRYABLE_ERROR_CODES` in `messaging/retry_policy.py`.
  - Messages encountering unavailable routes transition to `FAILED_RETRYABLE` and hold in SQLite durable queue under exponential backoff.
  - Persist both `active_transport` and `auto_failover` in SQLite `system_settings` table, refreshed on every worker delivery pass via `resolve_dispatch()`.

### T-04-02: DMR Chunk Header Overrun, 280-Byte Ceiling Violation & Corrupted Multi-Burst Reassembly
- **Threat:** Prepending a 4-byte chunk header to a 280-byte payload slice creates a 284-byte frame, violating the physical DMR Tier-II burst ceiling and causing physical radio rejection. Furthermore, if intermediate chunks fail over lossy RF links, partial message reassembly could cause payload corruption.
- **Impact:** Radio transmission rejection, illegal over-the-air burst sizing, and recipient payload corruption.
- **Mitigation:**
  - Maximum chunk payload slice is strictly $280 - 4 = 276\text{ bytes}$. Total chunk byte length is capped at 280 bytes.
  - Enforce atomic frame retries: If transmission of chunk $k$ fails, the router aborts the burst immediately, marks the attempt failed, and re-transmits all chunks sequentially from chunk 0 on subsequent backoff retry window.

### T-04-03: Accidental Physical RF Commanding or Keying on Unauthorized STAR-V Tactical SDR
- **Threat:** Direct invocation of transmitter commanding or automated fallback routing onto the STAR-V tactical radio could attempt unauthorized RF keying, risking statutory FCC/defense transmission violations, equipment damage, or COMSEC key compromise.
- **Impact:** Legal telecommunications violations, electronic detection, and radio cryptographic lockout.
- **Mitigation:**
  - `StarVAdapter.readiness` is permanently set to `TransportReadiness.LOCKED_OUT`.
  - `StarVAdapter.supported_operations` is empty (`[]`).
  - `StarVAdapter.command_transmit()` raises fatal `StarVSafetyLockoutError`.
  - Outbound dispatch attempting to key STAR-V logs high-severity `STARV_SAFETY_LOCKOUT_BLOCKED` audit events and prevents physical transmission with zero software override.

### T-04-04: Depleted Relay Node Blackout & Flight Avionics Coupling
- **Threat:** A relay node with critically depleted battery or full storage attempts forwarding, causing power brownout or silent storage packet drop mid-flight. Alternatively, aerial relay payload communications software interfaces with vehicle flight controls.
- **Impact:** Loss of in-flight communications, relay storage corruption, or catastrophic drone flight safety failure.
- **Mitigation:**
  - Autonomous failsafe cutoff: `RelayNode.can_forward_to()` returns `False` when battery $\le 5\%$ or storage $\ge 98\%$.
  - Aerial relay nodes are verified to have `flight_failsafe_independent = True`, guaranteeing payload communications have zero coupling to vehicle flight avionics.
</threat_model>

     for idx, chunk in enumerate(chunks):

             # Any chunk failure invalidates the entire burst attempt.
