<threat_model>
### T-05-01: Model Checkpoint Tampering, Bit Rot, or Unverified Neural Inference
- **Threat:** If an unverified or corrupted neural model checkpoint is loaded into memory, adversarial backdoors or corrupt model weights could degrade LPI stealth margins, emit detectable RF signatures, or produce silent bit errors.
- **Impact:** Compromised operational stealth, RF detection by adversary electronic surveillance, and payload corruption.
- **Mitigation:**
  - `SDRResearchService.verify_checkpoint_bundle()` verifies the SHA-256 digest against `export_manifest.json` (`0e8e515355be8bffb48fc27ad63b8e4a4aead57b72d2b5ad969d58aeb1c0887c`).
  - If digest does not match, neural weights are rejected (`torch.load()` is blocked) and the system activates analytical Gaussian pseudo-random IQ fallback.
  - Verification results are recorded in SQLite `security_audit_logs`.

### T-05-02: Simulated Tamper Desynchronization & Silent Failure of Fallback
- **Threat:** If an operator simulates a tamper event but the backend fails to activate analytical fallback or fails to log the security audit event, operators would have false confidence in the tamper-defense subsystem.
- **Impact:** Undetected failure of defense mechanics, potential crash in signal visualization pipelines.
- **Mitigation:**
  - `simulate_tamper(active: bool)` sets `_tamper_simulated = active` in memory without mutating files on disk.
  - `get_signal_sample()` checks `_tamper_simulated` and immediately diverts to `SYNTHETIC_ANALYTICAL_FALLBACK` with explicit flags `fallback_active: True` and footnote.
  - High-severity audit log `MODEL_CHECKPOINT_HASH_MISMATCH` is durably written to SQLite.

### T-05-03: Apple Silicon PyTorch MPS ComplexFloat Kernel Crash
- **Threat:** PyTorch MPS does not support `ComplexFloat` operations. In `LPIDecoder.blind_phase()`, carrier phase synchronization invokes `torch.polar()` or complex arithmetic, throwing an unhandled `TypeError` that crashes inference workers.
- **Impact:** Service crash on Apple Silicon hardware, 500 API errors, and broken receiver pipeline.
- **Mitigation:**
  - Hybrid acceleration strategy: `LPIGenerator` (real-valued convolutions and activations) executes on MPS.
  - `LPIDecoder` executes on CPU or decomposes complex arithmetic to real-valued components ($\text{atan2}$, $\cos$, $\sin$).
  - Any MPS execution is wrapped in `try...except (TypeError, RuntimeError)` with automatic fallback to CPU, recording `fallback_active` in environment telemetry.

### T-05-04: Flowgraph Parameter Drift & Accidental Unauthorized Band Transmission
- **Threat:** If top-level GNU Radio flowgraphs (`grc/tx_lpi_cgan.grc`, `grc/rx_lpi_cgan.grc`) maintain legacy parameters (750 MHz carrier, 1 MS/s sample rate) while core scripts operate at 2.484 GHz and 245.76 kS/s, SDR transceivers will experience frequency mismatch, loss of synchronization, and potential transmission in unauthorized spectral bands.
- **Impact:** Communication failure, spectral spillover, and regulatory violation.
- **Mitigation:**
  - Harmonize all flowgraph YAML blocks to `center_freq: 2484000000` (2.484 GHz ISM Channel 14) and `samp_rate: 245760` (245.76 kS/s).
  - Update compiled Python runners to match.
  - Validate with automated YAML parser test asserting exact parameters across all flowgraphs.
</threat_model>
