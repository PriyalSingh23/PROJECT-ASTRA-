<threat_model>
### T-02-01: Sensitive Credential Leakage in Audit Event Telemetry
- **Threat:** Unsanitized message event metadata or error details could inadvertently expose cryptographic keys, PBKDF2 hash fragments, or internal tokens in the client telemetry drawer.
- **Impact:** Compromise of message envelope confidentiality or server authentication tokens.
- **Mitigation:**
  - In `messaging/worker.py`, `safe_metadata` must strictly record only non-sensitive operational identifiers: `worker_id`, `lease_expires_at`, and `attempt_number`.
  - In `MessageTelemetryDrawer.tsx`, the raw JSON metadata viewer filters and sanitizes any sensitive keys before rendering.
</threat_model>

```python
if rows > 0:
    # Log explicit LEASE_ACQUIRED audit event
    lease_event = MessageEvent(
        event_id=generate_uuid(),
        message_id=candidate_id,
        event_type="LEASE_ACQUIRED",
        timestamp=now,
        source_endpoint=self.worker_id,
        safe_metadata={
            "worker_id": self.worker_id,
            "lease_expires_at": lease_expiry.isoformat(),
        },
    )
    session.add(lease_event)
    session.commit()

    # Successfully acquired atomic lease!
    leased = session.query(Message).filter_by(message_id=candidate_id).first()
    return leased
```
